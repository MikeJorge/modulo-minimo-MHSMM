Architecture diagram of the Module Minimum scientific software development system. At the top, three certified authorities—the Scientific Execution Architecture v1.0.2, Software Development and Assurance Manual v1.0.1 RC3, and Project Evidence Base v1.0.0—converge on the non-normative controlled Methodology v1.0.1. The middle left contains the certified four-plane execution-control infrastructure (Control, Execution, Authority, and Evidence/Provenance) plus a separate cross-cutting Data/Catalog governance layer and a small historical local execution-adapter inset. The center contains six bounded scientific modules: Environment, Plant, Animal, Economic, Integration Core, and Data Catalog. A single arrow leaves the module region and enters the permitted inter-module path at Module Output, followed in order by Versioned Data Contract, Catalog Record, Provenance/Evidence Binding, Integration Adapter, and Consumer Module. The lower section shows a nine-stage Gate-governed lifecycle from scientific need and requirements through architecture, design, implementation, verification, validation, independent assurance, and freeze. Verification and validation are defined separately, and internal MM assurance is explicitly not formal external IV&V. A spatially separate bottom band states that frozen or certified status is not runtime authorization and lists five distinct runtime classes without marking any as authorized. Colour is used only as a redundant grouping cue; labels, borders, line styles, and position carry the same semantics.
